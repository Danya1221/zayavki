# zayavki — оформление заказов и мини-CRM в Telegram

Бот оформления работает со своей базой данных. [rozniysa](https://github.com/Danya1221/rozniysa)
передаёт ему каталог по защищённому HTTPS API. Проекты могут находиться в разных
проектах Railway: общая PostgreSQL и доступ к чужой базе не нужны.

Нажатие на товар в прайсе открывает обычный Telegram-бот с нужным вариантом в корзине.
После «Оформить» бот сразу спрашивает имя, телефон и способ получения.
Сведения продавца, ссылки на документы и адрес самовывоза не требуются в Variables.

## Что умеет

- Корзина до 30 разных товаров, до 20 штук на позицию; примечания к товарам и этапам.
- Телефон приводится к российскому `+7`; город, улица, дом и квартира проверяются по формату.
  Проверка адреса по справочнику и SMS-подтверждение номера не выполняются.
- Курьер, транспортная компания или самовывоз. Место и время самовывоза согласует менеджер.
- Доставка платная: администратор вводит сумму, клиент подтверждает итог; после изменения
  стоимости подтверждение запрашивается заново. Самовывоз — без стоимости доставки.
- Клиент видит только свои заявки. Администраторы из `ADMIN_IDS` видят устройства,
  варианты, цены, количество, контакты, Telegram ID/username, адрес и примечания.
  Внутренние заметки доступны только администраторам.
- Статусы: новая, в работе, сборка, у курьера, готов к выдаче, завершено, отменено,
  возврат, брак. Статусы можно добавлять, переименовывать, упорядочивать и отмечать завершающими.
- Завершённые заявки сразу уходят из активного списка в архив на **7 суток**.
  Затем удаляются при ближайшей очистке. Открытый заново возврат/брак остаётся активным.
- Приветствие сохраняется. Черновик очищается после 24 часов бездействия или при изменении
  цены/доступности позиции в корзине. Отправленная заявка сохраняет снимок состава и цен.
- Ночью и при сбое поставщика заявки принимаются с необходимостью подтвердить наличие.
  Заявка не резервирует товар у поставщика.

## Настройка Railway — сначала этот проект

1. Подключи этот репозиторий, ветку `main`, к сервису `zayavki`. Одна реплика.
   Dockerfile и команда `python -u main.py` уже заданы.
2. Подключи **свою базу этого проекта** через `DATABASE_URL`.
   Если сервис базы называется `Postgres`, в Variables можно указать:
   `DATABASE_URL=${{Postgres.DATABASE_URL}}`.
3. Укажи `BOT_TOKEN` бота оформления, свой `ADMIN_IDS` и `SYNC_API_KEY`.
   Ключ обмена — случайная строка 32–128 латинских букв, цифр, `_` или `-`.
   Одинаковый ключ впиши в `rozniysa`. Токены Telegram у ботов разные.
4. Добавь `PORT=8080`, сохрани Variables и примени Deploy.
5. Открой Settings → Networking → Public Networking → **Generate Domain**.
   Если Railway спрашивает target port, укажи `8080`.
   Этот домен нужен для приёма каталога, а не для Telegram webhook.
6. Открой `https://ТВОЙ-ДОМЕН/health`: должен вернуться JSON с `ok: true`.
7. Передай HTTPS-домен без `/health` в `CATALOG_API_URL` проекта `rozniysa`.
8. Каждый администратор открывает бота в Telegram и нажимает `/start`.
   Управление заявками — `/admin`.

[Настройка домена Railway](https://docs.railway.com/networking/public-networking)
и [переменных](https://docs.railway.com/variables).

## Переменные

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен бота оформления |
| `ADMIN_IDS` | Числовые Telegram ID администраторов через запятую |
| `DATABASE_URL` | PostgreSQL **этого** проекта |
| `SYNC_API_KEY` | Одинаковый секрет обмена каталогом в обоих проектах |
| `PORT` | HTTP-порт API; в примере 8080 |
| `SHOP_NAME` | Название магазина, необязательно |
| `CATALOG_URL` | Необязательная ссылка на прайс; обычно передаётся через API |
| `ARCHIVE_DAYS` | Архив, по умолчанию 7 суток |
| `DRAFT_HOURS` | Черновик, 1–24, по умолчанию 24 часа |
| `CATALOG_FRESH_SECONDS` | Свежесть исходного прайса, по умолчанию 1800 секунд |

Пример Variables — `.env.example`. Старый `RETAIL_DATABASE_URL` принимается только
как запасное имя, если `DATABASE_URL` отсутствует. Он больше не означает общую базу.
Не меняй URL существующей базы заявок без переноса данных: смена URL не переносит заказы.

## Связь и устойчивость

`POST /api/catalog/sync` принимает только снимок каталога, отметку о недоступности
поставщика и ссылку на прайс. Нужен заголовок `Authorization: Bearer <SYNC_API_KEY>`.
API не предоставляет чтение/изменение заявок, контактов или администраторов.
`GET /health` — открытая проверка доступности без данных клиентов.

У каждого обновления есть возрастающий номер. Каталог и номер применяются одной
транзакцией: повтор безопасен, запоздавшее обновление не возвращает старые цены.
Ошибка проверки одной позиции отклоняет весь снимок; текущий каталог сохраняется.
При временном разрыве связи остаётся последний каталог, а его свежесть считается
по исходному времени проверки поставщика, а не по времени HTTP-повтора.

Протокол v1: `protocol`, `revision`, `operation`; операции `snapshot`, `uncertain`,
`catalog_url`. Снимок включает `products`, `confirmed`, `checked_at`; товар — стабильный
`id`, `title`, `brand`, `section`, `price`, `currency` и необязательные характеристики.
Ограничение: 30 000 позиций / 20 МиБ на запрос. Денежные значения — строки Decimal.
Изменение цены сбрасывает черновики, но не переписывает оформленные заказы.

## Очистка

Telegram ограничивает [удаление старых сообщений](https://core.telegram.org/bots/api#deletemessage)
возрастом 48 часов. Если удалить карточку нельзя, её текст заменяется нейтральным,
а кнопки убираются. Приветствие сохраняется. Входящие контакты и адреса удаляются из
переписки после обработки. Очистка выполняется, пока сервис работает, и продолжается
после простоя. При недоступном Telegram сообщения могут очищаться позже базы.
Пересылки, пользовательские копии и бэкапы хостинга бот не контролирует.

При неподтверждённой Telegram отправке уведомление не повторяется вслепую;
заявка всё равно доступна в `/admin`. Архив на 7 дней задаёт срок хранения;
код не отклоняет обращения автоматически по истечении этого срока.

## Разработка и тесты

Python 3.12. Локально `DATABASE_URL=sqlite:////absolute/path/orders.db`;
у витрины должен быть другой файл. Для Railway — постоянная PostgreSQL.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполни .env
python main.py
```

```bash
python -m compileall -q .
python -m unittest discover -s tests -v
TEST_DATABASE_URL=postgresql://... python -m unittest discover -s tests -v
```

**Тесты очищают `retail_data` в `TEST_DATABASE_URL`: используй только отдельную тестовую базу.**
GitHub Actions проверяет оформление, авторизацию API и атомарность на SQLite/PostgreSQL.
В `rozniysa/tests/integration_pair.py` проверяется реальный HTTP-обмен двух отдельных баз:
прайс → корзина → заявка → доставка → изменение цены → архив.
